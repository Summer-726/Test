# 需求分析：AI 经济顾问（微信小程序 · 测试版）

> 需求状态：**已定稿**（尚未开始开发） · 最后更新：2026-08-10
> 本文件是我们讨论需求的唯一记录，后续所有确认与修改都在此更新。

## 1. 项目概述

一个面向"没有独立收入的学生"的 AI 经济顾问。核心是解决两个痛点：**无意识超支**、**花钱没有换来相应的情绪回报**。

**什么是"情绪回报"**：衡量一笔消费"值不值"的关键指标——花的钱是否换来了相应的快乐/价值感。量化机制（已定方向）：不直接让用户打主观分，而是回答**简单客观问题 + AI 评定**（具体问题清单待确认，详见 §6.1）。

与普通记账软件的区别：它不是一个记录工具，而是一个**带着用户真实账本的 AI 顾问**——能主动提醒、分析"这笔钱花得值不值"、在冲动消费前帮用户冷静决策。

## 2. 目标用户

- 没有独立收入、生活费主要来自父母/亲戚的学生
- 每月有一笔生活费，但对自己"钱花哪了、花得值不值"没有清晰感知
- 高频使用微信（故选择微信小程序形态）

## 3. 价值主张与差异化

- **不只是记账**：市面上记账软件只记录数字，本项目由 AI 主动分析"情绪回报"
- **数据护城河**：拥有"每笔消费 + 心情打分"的情绪账本，这是任何通用 AI 都没有的
- **主动顾问**：预算预警、冲动消费前拦一下、月度复盘建议

## 4. 已确定的产品决策

| 决策点 | 结论 |
|---|---|
| 产品形态 | 微信小程序测试版（手机端更便捷，符合目标用户习惯；原"浏览器网页版"方案已放弃） |
| 记账方式 | 手动记账（描述式：输文字，AI 自动分类）；自动识别留到以后（原因见 §5.1） |
| AI 方案 | DeepSeek API + 提示词（顾问手册）+ 实时账本数据（RAG）；不做训练/微调（原因见 §5.2） |
| 隐私 | 账目数据存手机本地；仅 AI 对话时经微信云函数转发必要数据 |
| 用户范围 | 单用户（测试版主要给自己用，数据存手机本地，不做多账号）；无独立登录注册（微信自带自动登录，打开即用，不自己建账号系统） |
| 界面语言 | 中文 |
| 开发工具 | 微信开发者工具（需要用户本人安装 + 注册小程序 AppID） |
| 开发语言 | 不限（由开发者选择最合适的技术），用户不参与底层逻辑开发，代码由开发者完成 |

## 5. 技术方案与选择理由（讨论记录）

### 5.1 为什么记账以"手动"为主

- **最初设想**：自动识别每天的支出，做到无感记账
- **现实约束**：
  - iPhone（iOS）：苹果沙盒机制，任何 App（含原生 App）都无法读取微信等别的 App 的内部数据；小程序也没有任何官方 API 能读取"微信支付历史账单"
  - 安卓（Android）：需"读取短信 / 无障碍服务"等敏感权限，且微信小额支付大多不发短信、通知读取不稳定、隐私代价大
- **最接近"自动"的现实方案**：微信账单文件导入——用户在微信导出官方账单 → 小程序导入，AI 自动识别分类。缺点：只覆盖微信支付（支付宝 / 现金 / 校园卡覆盖不到）、导出流程略繁琐（设密码 / 发邮箱）；且导入的只有"金额 + 商家"，心情/值得度数据仍需手动补。这也是随手记、鲨鱼记账等专业 App 实际在用的方案
- **结论**：测试版用手动记账（描述式：输文字，AI 自动分类，3 秒一笔，可顺手标记心情）；"账单导入"列为未来增强（见 §11）

### 5.2 为什么用"DeepSeek API + 提示词 + RAG"，不训练、不微调

- **用户最初的顾虑**：直接用通用模型，会不会"太没特色、没专攻"
- **结论**：特色不来自模型本身，来自三样东西——
  1. **提示词（"顾问工作手册"）**：告诉 AI"你的用户是没有收入的学生、语气温和但直接、帮用户分清需要与想要、不做投资建议……"
  2. **实时账本数据（情绪账本）**：每笔消费 + 心情打分，通用 AI 没有
  3. **产品逻辑**：超支提醒规则、花钱决策框架、情绪回报分析方式
- **训练层次说明**（为什么不做训练）：
  - 从零预训练：成本数百万美元级，个人无法做、也不需要做
  - 微调：只能改变模型"说话风格"，但补不了"用户每天的实时个人数据"，对私人顾问反而会僵化
  - **提示词 + RAG（本次采用）**：每次对话实时喂"顾问手册 + 用户账本"，这正是经济顾问"专攻"的来源
- **模型可替换**：专业性写在提示词和数据层，未来可换 Kimi、Claude 等，无需大改

### 5.3 隐私设计

- 账目数据存手机本地，不上传云端
- DeepSeek API key 存放在云函数环境变量中，不暴露在小程序前端代码
- 数据流：用户提问 + 最近消费记录 → 经云函数转发给 DeepSeek → 返回回答
- AI 建议定位"参考 + 教育"，不做投资建议

### 5.4 成本（测试版）

- 微信云开发：测试阶段（不发布上线）可用免费体验环境；长期上线后个人版约 19.9 元/月
- DeepSeek 调用：按 token 计费，个人测试用量很低、费用可忽略

## 6. 功能需求

### 6.1 记账（数据入口，要快）

**录入方式（移动端优先）：**
- **金额**：弹出纯数字键盘（带小数点）触屏输入
- **描述**：用户输入一段简短文字（如"和朋友看了场电影"），**不手动选分类**
- **AI 自动分类**：AI 根据描述归类到固定分类集合（餐饮/交通/购物/娱乐/学习/其他），原始文字保留为备注；AI 失败时兜底为"其他"，用户可手动改分类
- **情绪评价（值得度）**：记账完成后出现**轻量可选提示**"这笔要评一下吗？"（必要开销如吃饭、买水可直接跳过）；也可事后在消费列表补答。方向已定——不直接打主观分（机制见下方"值得度评分"）
- 日期默认当天，可改
- **支出 / 收入切换**：默认记支出；切到"收入"可录入额外收入（亲戚给的零花、兼职收入等），来源写进描述，自动累加到本月总收入参与分罐
- **扣款来源（三罐）**：默认从"花罐"扣除；两个小按钮可切换为从"救急罐"或"存罐"扣除

**值得度评分（测试版方案）：两问 + AI 评定**【测试版简化版，未来可完善】
- 不做主观打分，也不依赖论文公式
- **评价是"可选动作"，不是每笔的负担**：
  - 记账完成后，出现轻量提示"这笔要评一下值不值吗？"——用户自主选择评或跳过
  - 必要开销（吃饭、买水等）自然跳过，无需回答；事后也可在消费列表里对某笔补答
- 机制：用户对选中的消费回答**两个简单客观的问题** → AI 结合回答 + 上下文（金额、分类、当时预算状况、历史同类消费）判定"值 / 一般 / 不值"并解释原因
- **两问（已定）**：
  1. 这笔消费，是**需要**还是**想要**？（需要 / 想要 / 说不清）
  2. 如果能回到付钱前，你还会**再花一次**吗？（会 / 不会 / 不确定）
- **"回味 / 长期情绪价值"维度不靠逐笔问答**：由 AI 在点评时根据消费规律分析（例："这类娱乐消费你标了'会再花'但后悔率偏高，说明短期开心、长期不值"）
- **情绪评价不是 AI 建议的前提**：即使一笔都没评，AI 也能凭消费数据（金额 / 分类 / 时间 / 预算状态）给出超支预警、分类分析和消费建议；值得度只是让"洞察"和点评更有深度
- 备注：两问是**测试版简化方案**；评价体系（问题数量、维度、权重）预留扩展空间，验证后迭代

### 6.2 预算与状态（专治"无意识超支"）

**核心逻辑：本月总收入 → 按比例分成三个罐子 → 预警只盯"花罐"**

- **本月总收入**：月初生活费 + 月中新增收入（亲戚给零花、兼职收入等，录入一笔"收入"自动累加）
- **三罐分配（比例可调，甚至 100/0/0）**：
  - **花 🛍️**：日常能花的钱 → 就是"预算上限"，预警盯它
  - **救急 🧯**：生病、东西坏了等真急事才动用
  - **存 🧊**：攒下来的钱；设置时先询问有无存钱计划——有 → 配一个目标进度条（如"攒 ¥3000 换手机"）；无 → 只累计金额
- **记账扣款来源**：默认从"花罐"扣除；记账页提供两个小按钮，可切到从"救急"或"存"扣除（每笔消费本就有文字描述，无需额外的"紧急说明"流程）
- **打开页面始终显示**：三罐余额 / 花罐剩余 / 剩余天数 / 日均可用
  ```
  本月 ¥1500 → 花 ¥1050 ｜ 救急 ¥225 ｜ 存 ¥225
  花罐已花 ¥920 ｜ 剩 ¥130 ｜ 剩 20 天
  日均还能花 ¥6.5 ⚠️
  ```
- **AI 预测预警**：按最近消费速度预测"照这速度月底会花多少、会不会超支"，提前警告（例："本月已过 10 天，日均 ¥46，照这速度月底约 ¥1380；但按你这周的速度会超支约 ¥150，建议接下来日均控制在 ¥40 以内"）
- **超支预警触发（已定）**：花罐花到 70% 提醒一次、90% 再提醒一次；花罐见底后继续花（动用救急/存）时提示"你正在动用救急金/存款"
- **跨月规则（已定）**：花罐每月重置；救急罐、存罐余额跨月保留（这样才能攒存钱目标）

### 6.3 AI 顾问对话（核心差异化）

- **常驻聊天入口**：底部固定"问 AI"页，随时可问，例如"想买个 300 块的耳机，该不该买？""我这个月钱花哪了？"
- **汇报按钮（随时可点）**：
  - **今日汇报**：任意时间可点（当天没花钱也能生成），AI 以顾问口吻输出今天的总结：
    - 今天在哪些方面花了多少钱（按分类）
    - 整体情绪如何（基于当天已标记情绪评价的消费；没标记则给出基于描述的观察 + 提醒下次顺手标记）
    - 给出 1~3 条具体建议
  - **本月汇报**：任意时间可点，原理相同，范围变成"本月至今天"（主动生成；区别于月底自动的"月度回顾"，见 §6.5）
- **回答机制（RAG）**：提问或生成汇报时，云函数带上"顾问手册（提示词）+ 最近消费记录 + 三罐预算状态 + 情绪数据"发给 DeepSeek，返回回答；只在需要时转发，不外传不保存
- **回答风格**：温和但直接，帮用户分清"需要 vs 想要"；定位"参考 + 教育"，不给投资建议，界面有免责提示
- **聊天历史（已定）**：保留，可跨页面、跨会话接着聊；记录存手机本地，隐私优先（代价：每次调用携带的历史上下文更多、token 消耗略高）
- **开场白**：打开问 AI 页时，顾问主动说当前状况（预算进度、最近后悔消费），而非干等用户提问

### 6.4 情绪回报分析（本项目最独特的模块）

回答的问题："我这个月的钱，花得值不值？"

- **页面结构**：
  1. 顶部一句话总结：AI 点评"本月最值 / 最后悔"（例："最值的是和朋友的这顿饭 ¥58；最不值的是那笔 ¥180 的盲盒，你标了'后悔'"）
  2. 按分类的"花费金额 + 后悔率"图表（一眼看出钱都去哪了、哪类最容易花完后悔）
  3. 逐笔回顾：按后悔程度排序，最值得的在前、最后悔的在后，方便翻看复盘
- **AI 点评（已定）**：除数值图表外，加**针对性文字建议**（例："购物类后悔率高，下次买 ¥200 以上的东西前先问问我"）
- **数据来源**：§6.1 的"值得度"评分（简单问题 + AI 评定）；测试版第一版可先只显示"花费金额按分类分布"，情绪部分逐步填充
- **对应初始痛点**："钱花出去到底值不值"

### 6.5 月度回顾（月底自动生成）——与"月度汇报"区分开

- **两个概念分开**：
  - **月度汇报（主动）**：用户在任意时间主动点"本月汇报"，看"本月至今天"的情况（归在 §6.3 汇报按钮里，原理同日报）
  - **月度回顾（自动）**：一个月结束时**自动生成**《本月经济报告》，对**整个已结束的月**做总结，无需用户点击
- **月度回顾内容**：
  1. **总览**：本月总收入（生活费 + 额外收入）、三个罐子最后结余、超支了吗
  2. **钱去哪了**：各分类花费排行，一眼看懂大头
  3. **值得复盘**：哪些钱花得值、哪些后悔（依赖值得度数据）
  4. **下月 3 条建议（已定，含协商流程）**：AI 先给出**建议草稿** → 用户过目、修改、确认后 → 才存为"下月提醒"，下月 1 号显示在首页继续执行。**用户有最终决定权，AI 不替用户做主**；具体内容在月底/月初确定
  5. **对比上月**：比上月花多/少了？消费习惯有什么变化
  6. **归档**：报告按月存档，可回看历史月份

## 7. 互动设计

- **记账 + AI 自动分类（独立功能，也是咨询的前提）**：单独列为一类，不与咨询混为一谈。所有汇报、分析、预警都建立在"有账可查"之上——先记账，后咨询
- **被动咨询**：常驻"问 AI"入口，随时可问（"想买 X 该不该买""我这个月钱花哪了"）
- **主动汇报**：今日汇报 / 本月汇报按钮，随时点，AI 以顾问口吻做总结、给建议
- **主动提醒（已定）**：打开小程序时，顾问卡片自动显示当前状态（三罐进度、花罐剩余、最近后悔消费提示）；月度回顾月底自动生成；下月提醒下月 1 号显示。订阅消息推送列为可选增强（测试版不做）

## 8. UI 结构（视觉追求：极简、苹果风，见 §9 设计原则）

- **底部 4 个 tab**：首页 / 记账 / 问AI / 洞察
- **首页概览**：三罐状态卡（花罐占主位，救急/存辅助显示）+ 今日/本月汇报按钮 + 顾问提醒卡片 + 最近 5 笔消费
  - 点"三罐状态卡" → 进入「预算」页
- **预算页**（页内分段切换 [ 预算 | 规划 ]）：
  - **预算**：本月生活费、三罐比例、是否启用预警提醒
  - **规划**：存钱目标（新增 / 进度 / 历史完成）
- **记账页**：金额数字键盘 + 描述输入（AI 自动分类）+ 支出/收入切换 + 扣款来源三选一（花/救急/存）+ 日期
- **问 AI 页**：聊天界面（保留历史），顾问基于数据说开场白
- **洞察页**：各分类"花费 + 后悔率"图表 + AI 点评（最值/最不值）+ 文字建议

界面技术：微信小程序（WXML / WXSS / JavaScript）。全部代码由开发者完成，用户不需要自己写代码。

## 9. 非功能需求

- 账目数据存手机本地（wx 本地存储），隐私优先
- DeepSeek API key 存放在云函数环境变量中，不暴露在小程序前端
- 代码简单、有中文注释，便于新手理解维护
- AI 建议定位为"参考 + 教育"，界面有免责提示
- **UI 设计原则（苹果风，重要）**：极简克制的配色（中性色为主 + 少量强调色）、大留白、清晰的文字层级、圆角卡片、细腻动效；目标"干净、高级、打开就会用"。开发时先出高保真原型逐屏打磨，视觉允许迭代调整

## 10. 需求确认清单（2026-08-10 全部确认完毕）

**已确认的关键决策**：
- 产品形态：微信小程序（见 §4）
- 分类方式：用户输文字，AI 自动归类到固定分类集合（6 类），失败兜底"其他"
- 三罐子分配（花 / 救急 / 存，比例可调，可 100/0/0）；记账默认扣花罐、可切换
- 存钱罐配"目标"：设置时先询问有无存钱计划
- 救急 / 存罐余额跨月累计，花罐每月重置
- 值得度评价：记账后**可选**（轻提示，可跳过）；事后可补答
- **值得度评定方式：两问 + AI 评定**（需要/想要 + 还会再花一次吗；测试版简化版，未来可完善，见 §6.1）
- AI 顾问聊天历史保留（存手机本地）
- 下月提醒采用"AI 出草稿 → 用户确认"的协商流程
- 汇报体系：今日汇报 / 本月汇报（主动），月度回顾（月底自动）
- 超支预警：花罐 70% / 90% 两档
- 主动提醒：打开小程序时的顾问卡片；订阅消息推送测试版不做
- 账号设置步骤由用户本人完成（装工具 / 注册 AppID / 开通云开发 / 填 key）
- UI：底部 4 tab + 预算页分段（预算 / 规划）
